# Local / workstation dependency audit

Pre-24, Deliverable 11. A repository-wide search for hidden workstation dependencies — anything a normal restart or a fresh clone on another machine would need that isn't reproducible from Git. Run with `git grep` against tracked files only (never the gitignored `.secrets/`, `.env*`, `.terraform/`, `state/baselines/*/deployed/` — those are expected to hold machine-local material).

## What this audit did not do

It did not run against the gitignored `.secrets/`, `state/baselines/*/deployed/`, or `node_modules/` — those legitimately hold machine-local material by design (`docs/persistence.md`'s REISSUE class, and Prompt 00's own selected-field capture discipline). It did not attempt to fix findings 6-8 — each is a deliberate design decision or touches non-exportable key material, outside a persistence/rehydration prompt's scope to resolve unilaterally.

## `commit_gh --scan` / `--audit` (run for this prompt)

```text
commit_gh --scan    40 commits scanned, ~5.17MB working tree — no leaks found
commit_gh --audit   1 guardrail reported missing: .git/hooks/pre-commit
```

The one reported gap is a false positive from the audit tool checking the default hook location — this repository deliberately sets `core.hooksPath` to the Git-tracked `hooks/` directory instead (`make check` configures this automatically on a fresh clone; see `CONTRIBUTING.md`), and `hooks/pre-commit` is present, executable, and has been firing correctly on every commit made in this prompt (`sanity_check --fix` + Gitleaks staged-file scan, both observed live). Running `commit_gh --harden` to silence this would install a second, redundant hook mechanism at `.git/hooks/pre-commit` rather than fix an actual gap — not done.
