# Configuration reference

The repository `.env` is used by the Compose wrapper. Workload onboarding/provisioning may also write `.env.workloads`. Keep both private. `.env.example` is a template, not a working secret source.

Setting a variable in `.env` only affects a container if Compose passes it. Check the corresponding `environment`, volume and command declarations; do not assume every optional setting is wired into every service.

## Core settings

| Setting | Consumer | Purpose |
| --- | --- | --- |
| `VAULT_LICENSE` / `VAULT_LICENSE_ENT` | Vault stacks | Enterprise licensing; HSM instance may need a distinct feature set |
| `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` | Infra/Terraform | Initial database administration and Vault connection setup |
| `ARCANIUM_VAULT_ROLE_ID`, `ARCANIUM_VAULT_SECRET_ID` | Compose → API | Mapped to API `VAULT_ROLE_ID`, `VAULT_SECRET_ID` |
| `VAULT_ADDR` | API | Main Vault address, default `https://vault-1:8200` |
| `VAULT_CACERT` | API | Required path to trusted CA inside the container |
| `POSTGRES_HOST`, `POSTGRES_PORT`, `POSTGRES_DB` | API | Database location; user/password are obtained from Vault |
| `PORT`, `NODE_ENV` | API | Listener and runtime mode |
| `NUXT_ARCANIUM_API_INTERNAL` | UI server | API upstream, normally `http://arcanium-api:3001` |

The browser uses same-origin API transport. Never expose the internal Vault token, AppRole SecretID or database credentials via Nuxt public runtime configuration.

## Optional runtime capabilities

| Setting | Effect / default |
| --- | --- |
| `PROVISION_MODE` | `sync` by default; `queue` requires a worker |
| `VAULT_PROVISIONER_TOKEN` | Optional privileged identity for supported cross-namespace provisioning |
| `VAULT_HSM_ADDR` | HSM Vault metadata endpoint |
| `ARCANIUM_HSM_ROLE_ID`, `ARCANIUM_HSM_SECRET_ID` | Optional read identity for HSM metadata enrichment |
| `ARCANIUM_AUTH_ENABLED` | Human session enforcement; false by default |
| `ARCANIUM_DEMO_PERSONA_SWITCH` | Presentation-only persona switching; false by default |
| `ARCANIUM_BASE_URL` | The app's own public origin (default `http://localhost:3000`) — used both as the OIDC redirect base and as the exact `post_logout_redirect_uri` Keycloak must have registered for this client; the two must match |
| `ARCANIUM_OIDC_ISSUER`, `ARCANIUM_OIDC_CLIENT_ID`, `ARCANIUM_OIDC_CLIENT_SECRET` | The confidential OIDC client Express authenticates as |
| `ARCANIUM_OIDC_INTERNAL_URL`, `ARCANIUM_OIDC_PUBLIC_URL` | Keycloak's container-network address vs. its browser-reachable published address — deliberately two separate settings, not `host.docker.internal`; see [security.md](security.md) |
| `KEYCLOAK_ADMIN`, `KEYCLOAK_ADMIN_PASSWORD` | Realm bootstrap credentials, consumed by `compose/identity/keycloak/setup_keycloak.sh` |
| `WORKER_POLL_MS` | Worker polling interval; defaults to 3000 ms |
| `EVIDENCE_INGEST_ENABLED` | Enables worker audit-log ingestion when true |
| `AUDIT_LOG_PATH` | Audit input path the worker tails; Compose default `/vault/audit/vault-audit-r.log` (the world-readable file device) |
| `KMS_SIM_URL` | Emulated-KMS health probe target for the key-distribution panel; Compose default `http://arcanium-localstack:4566` |
| `OTEL_ENABLED` | Optional telemetry export; verify exporter configuration and running collector |

Authentication and provisioning have material operational effects. Consult [personas](personas.md), [orchestration](orchestration.md) and [security](security.md) before enabling them.

## HSM and workloads

`SOFTHSM_TOKEN_LABEL`, `SOFTHSM_SO_PIN` and `SOFTHSM_USER_PIN` configure token initialization/custody. The PKCS#11 proxy also requires `.secrets/hsm/pkcs11-proxy.psk` and the resolved slot file. Changing PIN values in `.env` does not reconfigure an already initialized token.

Workload variables include `DOCSIGN_*`, `SUPPLIER_*`, `APPROVER_*` and supplier-specific AppRole values generated by scenarios. Each workload's `src/config.*` and Compose environment define the actual contract. Regenerate only the credentials you intend to rotate.

## Configuration validation

```sh
make compose-config
```

Use quiet validation for automated checks. Expanded Compose configuration can include interpolated secrets; do not paste full output into tickets or documentation.
